Во входе есть подсказки кода:
- links: привязка сообщений без номера закупки. Есть purchase_id - бери его для изменений этого сообщения. inferred: true - поиск не подтвердил закупку или искать было нечего, и код взял единственную закупку истории; привязка все равно действует. purchase_id null - подходят несколько карточек из candidates: операций по этому сообщению не создавай, верни issue ambiguous_purchase с event_id.
- earlier: прежние сообщения закупок, на которые ссылается кусок ("как договаривались", "старое письмо"). Это прежние условия для сравнения, операции дают только сообщения из events.
- candidates: кандидаты из текста, найденные правилами: event_id, field, value, quote. Для каждого реши сам: agreed, offer, conditional или это не изменение карточки. Поле кандидата может быть неточным, выбери верное.
Деньги, количество и даты бери из candidates или из цитаты сообщения и не выдумывай: если значения нет ни там, ни там, операцию не создавай. Только delivered_quantity считай по правилу выше, как всего принятое.
